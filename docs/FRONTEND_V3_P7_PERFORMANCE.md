# P7 performance pass

Baseline device: 120 Hz Xiaomi 13 Pro (nuwa), b566c7d Debug. Ledger scroll P95 42 ms; detail open P95 40–77 ms (three attempts), return P95 93–109 ms; worst tab P99 150 ms; quick-entry P99 150 ms. GPU P99 typically 3–12 ms. These are scenario frame distributions, not tap-to-first-pixel latency. No claim of a Perfetto-proven call-stack bottleneck.

Changes: dedicated shared UI-only Room stream with bounded replay/idle lifetime (business reads stay cold and fresh), background ledger filtering/grouping/review indexing, coherent grouped ledger snapshot, bounded ViewModel warm state rather than keeping hidden UI trees composed. Detail history read only on demand; count off main with submit guard. Stats share current-range query, combine core UI state, subscribe only to visible period/tab, background aggregation. Calendar indexed rows and date cache, with unchanged drawer design. Amount text overflow uses width ratio and a shared bounded TextMeasurer cache; theme appearance local invalidation narrowed; remove duplicate keyboard inset in quick entry. Debug signing/test package unchanged; optional openMarginPerformancePreview=true disables debuggability without formal release signing. No new dependencies, SDK upgrade, capture or accounting rule changes, or VoiceFab state-machine modifications.

Acceptance: normal GitHub Actions plus local focused tests and equivalent ADB scenarios. Optional optimized preview is not a substitute for an ordinary Debug-to-Debug comparison. No device frame-time improvement is claimed until measured. Hidden page compositions are not retained: that would require a separate navigation/lifecycle audit. Complex form construction remains a possible follow-up if measurements identify it as dominant.
