# 疑似重复提示与账户字段

面向两个具体问题：

1. 手动记账（含语音预填）保存前没有任何相似账单检查，同一笔账可能被记两次；
2. `transactions.account` 列早就存在（Room v8），自动采集链路一直在写，但新建账单表单没有账户输入、
   语音/文字解析出的账户没写进表单、详情页只在有空值时补一句「未设置」。

边界先说清楚：**这篇文档描述的能力不改数据库版本、不改表结构、不改同步协议**。

## 一、保存前的疑似重复提示

### 1.1 触发点

| 入口 | 是否经过检查 | 说明 |
| --- | --- | --- |
| 新建账单弹窗，手填金额 | 是 | 点「保存」时先查候选，命中弹确认框 |
| 新建账单弹窗，只写一句话 / 语音预填 | 是 | 与手填同一条保存路径，解析后同样先查 |
| 详情页全字段编辑 | 否 | 改的是已有记录，不是新入账 |
| 通知 / 无障碍 / 短信自动采集 | 否 | 走 `TransactionRepository.insertIfNotDuplicate`，那里的自动合并、`reviewStatus`、`duplicateOfId` 逻辑完全不动 |
| 官方账单导入 | 否 | 走导入自己的去重（订单号 + 文件内重复），不改 |

语音不另写一套：语音识别结果只是把文字塞进同一个 `AddTransactionDialog`，保存仍然走 `onConfirm`，
所以检查天然覆盖语音路径。

### 1.2 判定规则（`DuplicateRule.find`）

金额必须**完全相等**（分为单位，整数比较），然后再看两个分支，任一命中即提示：

- **同商户分支**：时间差 ≤ **1 天**，且商户 normalize 后相等、或一方包含另一方；
- **短窗口分支**：时间差 ≤ **10 分钟**，不看商户。

商户 normalize：NFKC 全角转半角 → 小写 → 去掉空白、括号符号与常见标点（括号里的门店名保留）。
空商户（或 normalize 后为空）**永远不走**同商户分支，只剩 10 分钟窗口。

多条候选都命中时取**时间差最小**的一条；时间差相同取更早的一条，再相同取 `id` 小的，
保证同样的输入永远给同一个结果。

### 1.3 边界表

| 场景 | 结果 | 原因 |
| --- | --- | --- |
| 同金额 + 同商户，相隔 20 小时 | 提示 | 同商户分支，≤ 1 天 |
| 同金额 + 同商户，正好相隔 24 小时 | 提示 | 边界含等号（≤） |
| 同金额 + 同商户，相隔 24 小时零 1 毫秒 | 不提示 | 超出 1 天，且远超 10 分钟 |
| 同金额 + 不同商户，相隔 2 小时 | 不提示 | 商户不同只能靠 10 分钟窗口 |
| 同金额 + 任意商户，相隔 8 分钟 | 提示 | 10 分钟窗口不看商户 |
| 同金额 + 不同商户，正好相隔 10 分钟 | 提示 | 边界含等号（≤） |
| 同金额 + 不同商户，相隔 10 分零 1 毫秒 | 不提示 | 超出短窗口 |
| 金额差 1 分（36.50 vs 36.49） | 不提示 | 金额必须完全相等 |
| 金额为 0 或负数 | 不提示 | 这种金额本身就该被表单拦住 |
| 「星巴克(国贸店)」vs「星巴克（国贸店）」 | 提示（同在 1 天内） | 全角/半角括号、空格差异被 normalize 抹平 |
| 「财付通-星巴克」vs「星巴克」 | 提示（同在 1 天内） | 一方包含另一方 |
| 「星巴克(望京店)」vs「星巴克(国贸店)」 | 不提示（相隔 > 10 分钟） | 括号内门店名保留，不同门店不算同商户 |
| 单字商户「A」vs「AB」 | 不提示（相隔 > 10 分钟） | 包含匹配要求较短一方至少 2 个字 |
| 商户为空 vs「星巴克」，相隔 8 分钟 | 提示 | 空商户只走 10 分钟窗口 |
| 商户为空 vs「星巴克」，相隔 2 小时 | 不提示 | 空商户不参与同商户比较 |
| 3 条候选都在窗口内 | 只提示时间最近的一条 | 弹框一次只说一条，避免堆列表 |

规则**不含收支方向**：1 天内同金额的收入/支出极罕见，误报的代价只是多一次确认；
真正的风险（漏掉重复）比多问一句更贵。

### 1.4 候选查询（只读，不改表）

`TransactionDao.findAmountCandidatesAround(amountCents, windowStartMs, windowEndMs)`：

```sql
SELECT * FROM transactions
WHERE syncDeleted = 0 AND amountCents = :amountCents
  AND (remoteReviewStatus IS NULL OR remoteReviewStatus <> 'excluded')
  AND duplicateOfId IS NULL
  AND timestamp >= :windowStartMs AND timestamp <= :windowEndMs
ORDER BY timestamp DESC
LIMIT 100
```

- 时间窗口由 ViewModel 传 ±1 天（`DuplicateRule.SAME_MERCHANT_WINDOW_MS`）；
- `timestamp` 已有索引，扫描量按金额先收敛，不需要新索引、不需要改表；
- 已隐藏的重复副本（`duplicateOfId` 非空）和「不计入」记录不参与，否则用户会被一条列表里根本看不到的旧记录拦下来；
- 读库失败按「没命中」处理：查不了重复不应该拦住用户记账。

### 1.5 交互

点「保存」→ 按钮进入「正在检查…」并禁用（防连点）→

- 没命中：照旧入账、关闭弹窗；
- 命中：弹「可能重复」确认框，正文列出对方的时间、商户、金额、来源（微信 / 支付宝 / 银行短信 / 手动 / 其他来源），
  两个按钮：
  - **取消**（默认安全动作，点弹框外部/返回键同样是取消）：关掉确认框，回到表单，
    金额、商户、账户、时间一个都不丢，可以改完再存；
  - **仍然记这一笔**：按用户选择入账，两笔都保留。

**不自动合并、不静默去重、不删除任何一边**。用户可能真的连着买了两笔一样的（两杯咖啡、两次地铁）。

## 二、账户字段打通（不改表结构）

### 2.1 现状

`TransactionEntity.account: String?` 从 Room v8 起就存在，不是这次新加的：

- 数据库版本仍是 8，`BookkeepingDatabase` 的迁移链没动，没有新列、没有新迁移；
- 自动采集早就在写：微信/支付宝通知写「微信」「支付宝」；短信写「某银行 (末四位)」；
  无障碍支付成功页写「微信」「支付宝」；
- 缺的只是：新建账单没有账户输入、语音/文字解析出来的账户没进表单、详情页没有正经展示。

### 2.2 本次改动

| 位置 | 行为 |
| --- | --- |
| `AddTransactionDialog` | 新增「账户」一栏：微信 / 支付宝 / 现金 / 银行卡 / 不填，chip 单选，默认「不填」 |
| 编辑已有账单 | 打开时回填原值；原值是「招商银行 (1234)」这类不在预设里的自由文本时，额外显示一个选中态 chip，避免被改成「不填」 |
| 写入 | `account` 为空（或只有空格）存 `null`，**不存空串** |
| 编辑不填 | 清空成 `null`（`addTransaction` 与 `TransactionEditRules.applyTo` 同一口径） |
| `QuickEntryPrefill` | 新增 `account` 映射：`draft.account` 有值就带进表单；空/空白按「没解析出来」处理，不覆盖用户已选的值 |
| 语音解析 | 「微信支付」「微信零钱」并成预设「微信」（自动采集写的也是「微信」）；花呗、招商银行等具体账户原文保留 |
| 详情页 | 账户非空时多显示一行「账户：微信」；为空**整行不出现**，不再显示「未设置」 |

语音仍然只是录入方式：说「微信支付」只填**账户**，`source` 恒为 `MANUAL`，
不会因为一句话就把来源改成 `WECHAT`/`ALIPAY` 这种自动采集口径。

### 2.3 为什么账户不同步（边界）

账户**只存本地，不上传服务端**，这是既有设计，不是本次遗漏：

- 客户端 `SyncRecordFields` 的注释写明 `note` 与 `account` 有意缺席——通知/SMS 原文和银行卡提示不出手机；
- 服务端 `backend/app.py` 的 `Event` 模型同样没有 account 字段，上传契约测试
  （`backend/test_extraction_upload_contract.py`）断言上传行里**不含** `account`；
- 所以：换服务器等于换账本，本地账户值不会跟着过去；网页端也看不到账户；
- 想要账户跨端可见，需要同时改客户端上传结构、服务端模型与隐私口径——那是另一个决定，不在这次范围内。

## 三、测试与验收

纯 JVM 单测（`./gradlew testDebugUnitTest`）：

- `DuplicateRuleTest`：同商户 ±1 天命中、跨天边界、不同商户 2 小时不命中、10 分钟边界、
  金额不同不命中、括号/空格/大小写/全角差异仍命中、单字商户只认完全相等、
  空商户只走 10 分钟、多命中取最近、normalize 结果。
- `QuickEntryPrefillTest`：账户映射（有值带入、空白为 null、微信支付/零钱并到「微信」、
  支付宝/花呗/招商银行原文保留）。
- `EnglishUiTextTest` / `TranslationCoverageTest`：新增文案的中英对照。

**没有做的验证**：本轮只在 CI 上编译 + 跑单测，没有真机/模拟器验证。以下必须在真机上过一遍：

1. 新建账单选「微信」保存 → 详情页出现「账户：微信」；选「不填」保存 → 详情页没有账户那一行；
2. 现有的自动采集账单（账户「微信」）在新建时 → 命中 1 天内同金额同商户 → 弹出「可能重复」；
   点「取消」回到表单，刚填的内容还在；点「仍然记这一笔」两笔都在列表里；
3. 长按 + 号语音说「昨天中午在麦当劳花了 36 块 5，微信支付」→ 表单账户应为「微信」、来源应为手动；
4. 编辑一条账户是「招商银行 (1234)」的短信账单 → 表单里那个自定义 chip 是选中态，保存后账户不变；
5. 编辑时把账户点成「不填」保存 → 详情页不再显示账户行，数据库里是 `NULL` 而不是空串。
