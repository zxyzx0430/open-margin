# 清衡 V1.2.0 采集与导入收尾报告

- 日期：2026-11-15
- 范围：实时通知、页面识别/OCR、扫描结果直接入账、官方账单导入、去重、统计口径、分类
- 证据等级：Android JVM 单测 + 实际微信账单解析 + AOSP 模拟器导入；真机页面测试部分完成
- 隐私：本报告不记录真实姓名、商户明细或具体账单金额

## 1. 已完成

### 实时通知

- 微信/支付宝通知解析补齐：
  - 微信支付凭证、向商户支付、已支付、收款到账、退款到账；
  - 支付宝付款、收款、退款；
  - 新增个人转账收入/支出、零钱提现、红包收入/发出的通知解析；
  - 转账/提现/红包写入 `remoteReviewStatus="transfer"`，保留在账本但统计排除；
  - 拒绝验证码/动态密码/支付密码等敏感通知；
  - 拒绝“处理中、待支付、待确认、等待对方确认”等未完成状态；
  - 拒绝聊天消息标题，只接受微信支付/支付宝/服务通知/付款成功/收款到账等服务标题；微信红包标题单独允许，但仍要求“收到/领取了/已存入零钱”等已结算语义，避免把红包优惠券当成收入。
- 同一通知仍走 `insertIfNotDuplicate` 和通知指纹记录，不直接覆盖已有账本。

### 页面识别与 OCR

- 统一 `PaymentCardDetector` 覆盖微信/支付宝的支付、转账、红包、提现、退款、先用后付、账单卡片。
- 移植 huayoupu 的支付成功页严格判定规则与测试。
- 移植 PaddleOCR V6 Tiny（arm64）作为主 OCR，ML Kit 仅作非 arm64 回退。
- Android 14+ 优先按窗口截图；安全窗口失败时尝试整屏截图。
- 微信支付 secure 历史页验证结果：
  - 窗口截图返回 `ERROR_TAKE_SCREENSHOT_SECURE_WINDOW`；
  - 节点树只暴露部分内容，部分先用后付 WebView 内容不可读；
  - 因此该页面不能可靠自动 OCR。这不是权限问题，是 Android `FLAG_SECURE` 限制。
- 非 secure 页面仍可通过节点/截图 OCR 抓取；页面能暴露的先用后付记录可以抓到。

### 扫描结果直接入账

- 扫描到的已完成记录直接写入账本，不再只进入“待确认扫描结果”。
- 新增本地字段：`captureConfidence`、`captureKind`、`captureObservedAtMs`，不上传、不参与同步。
- 交易行显示置信度和账单日期；展开后显示采集时间。
- 去重键优先订单号；无订单号时使用来源、类型、金额、方向、商户和事件时间/时间桶；10 分钟内存窗口防止同一卡重复写入。
- 数据库版本 v8，7→8 非破坏迁移。

### 官方账单导入

- 实际微信账单解析：368 条有效，0 错误，49 条退款；分类修复后 65 条转账/红包。
- 映射：322 条支出，46 条收入。
- 重复导入校验：同一文件第二次导入 `reimportValid=0`。
- 跨来源去重：无单号通知/页面记录按来源、金额、方向、商户和 2 分钟窗口匹配；导入行有单号而旧记录无单号时，30 秒同事件窗口兜底。
- 预览阶段与确认阶段使用同一套精确 + 模糊去重，避免“预览 1 笔、确认 0 笔”的计数不一致。
- 退款行保留为 `refund` 状态，原始支出也保留但统计排除。
- 提现（方向 `/`）保留为转账类支出，统计排除。
- 修复 XLSX Excel serial 时间偏移：旧算法用 `Asia/Shanghai` 1899 年历史偏移 `+08:05:43` 作为锚点，导致所有时间早 343 秒；现改为先还原日历字段，再按目标时区现代偏移换算。实机导入第 19 行时间已恢复为 `2026-11-14 15:31:58 +08:00`（epoch `1794641518000`），并加 serial 单测。
- XLSX 预览行号按工作表真实行号显示，跳过空行也不会偏移。

### 分类

- 导入分类先用商户列匹配 `CategoryClassifier`，只有商户为空或为“微信支付/支付宝”等泛化名称时才用原始上下文；避免“交通银行/充值”等字段覆盖已识别商户。
- 复验发现的错分已修：中国电信→水电、自来充→水电、拼多多→购物、腾讯公益→其他、炸鸡店→餐饮、发给个人→转账并排除统计。
- 复验还发现“商户优先”会把个人转账/红包（商户只是人名）降级为 OTHER，导致统计虚高；现已同时检查原始账单字段中的转账/转入/转出/汇款/提现/发给/微信红包/信用卡还款提示，保留 transfer 排除。
- 转账提示只在商户本身无法分类时生效；已知商户不会被原始字段里的“红包”误判为转账。
- 最终实机导入分类核对：其他 83、购物 77、转账 65、餐饮 62、水电 57、娱乐 17、教育 4、交通 2、医疗 1。

### 导入统计口径

- 按现有规则排除退款、转账/提现、重复、不计入；统计金额已与实机数据库核对一致。
- 个人转账/红包（包括家人/朋友转入）按 `transfer` 口径排除，但记录仍保留在账本；如果产品希望把“个人红包/转账收入”计入收入，需要单独调整口径。
- 与微信官方汇总的差异来自退款和转账/提现被排除，属于现有产品口径，不是漏导。

### 权限与设置

- MIUI/HyperOS 不使用会空白弹回的详情 deep link，改为通用通知使用权/无障碍列表；AOSP 才用详情页。
- 通知权限、短信权限、应用设置都有回退路径。
- 设置页状态在返回后通过 `ON_RESUME` 重新读取。

### 其他 UI/UX

- 预览行显示退款/转账标签；预览摘要显示“其中 退款/转账”数量；日分组显示“不计入”数量。
- 收入空态改为“本月没有计入统计的收入（退款/转账已排除）”。
- 仍保留的 UI 观察：360dp 首屏信息密度偏高、FAB 滚动时会遮住部分行、筛选条滚动时会被列表顶部裁切；属于后续 UI 视觉整理，不影响数据正确性。

## 3. 当前完整流程

```text
支付发生
  ├─ 系统通知 ── 标题/正文解析（支付/转账/提现/红包/退款）── 去重 ── 入账
  │                                  └─ 转账/提现/红包标记 transfer，保留但统计排除
  ├─ 页面可见
  │    ├─ 无障碍节点卡片 ── 完成态判断 ── 扫描记录直接入账（带置信度/日期）
  │    └─ 节点不完整 ── 窗口截图 ── PaddleOCR/ML Kit ── 同一卡片解析 ── 入账/待核对
  └─ 无通知/secure 历史页
       └─ 官方 CSV/XLSX 导出 ── App 导入预览（精确+跨来源模糊去重）── 用户确认 ── 原子写入

银行短信 ── SMS 解析 ── 入账
手动记账 ── 直接入账
```

所有入口最终都进入同一账本和统计口径；退款、转账、提现、重复、不计入状态由现有规则排除。
