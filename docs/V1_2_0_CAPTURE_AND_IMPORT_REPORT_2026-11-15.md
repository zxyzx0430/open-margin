## 1. 已完成

### 实时通知

- 微信/支付宝通知解析补齐：
  - 微信支付凭证、向商户支付、已支付、收款到账、退款到账；
  - 支付宝付款、收款、退款；
  - 新增个人转账收入/支出、零钱提现、红包收入/发出的通知解析；
  - 转账/提现写入 `remoteReviewStatus="transfer"`，保留在账本但统计排除；**收到的红包计入收入**，发出的红包仍按 transfer 排除；
  - 拒绝验证码/动态密码/支付密码等敏感通知；
  - 拒绝“处理中、待支付、待确认、等待对方确认”等未完成状态；
  - 拒绝聊天消息标题，只接受微信支付/支付宝/服务通知/付款成功/收款到账等服务标题；微信红包标题单独允许，但仍要求“收到/领取了/已存入零钱”等已结算语义，避免把红包优惠券当成收入。
- 同一通知仍走 `insertIfNotDuplicate` 和通知指纹记录，不直接覆盖已有账本。

### 页面识别与 OCR

- 统一 `PaymentCardDetector` 覆盖微信/支付宝的支付、转账、红包、提现、退款、先用后付、账单卡片。
- 移植 huayoupu 的支付成功页严格判定规则与测试。
- 移植 PaddleOCR V6 Tiny（arm64）作为主 OCR，ML Kit 仅作非 arm64 回退。
- Android 14+ 优先按窗口截图；安全窗口失败时尝试整屏截图。
- 微信支付 secure 历史页验证结果：
  - 窗口截图返回 `ERROR_TAKE_SCREENSHOT_SECURE_WINDOW`；
  - 节点树只暴露部分内容，部分先用后付 WebView 内容不可读；
  - 因此该页面不能可靠自动 OCR。这不是权限问题，是 Android `FLAG_SECURE` 限制。
- 非 secure 页面仍可通过节点/截图 OCR 抓取；页面能暴露的先用后付记录可以抓到。

### 扫描结果直接入账

- 扫描到的已完成记录直接写入账本，不再只进入“待确认扫描结果”。
- 新增本地字段：`captureConfidence`、`captureKind`、`captureObservedAtMs`，不上传、不参与同步。
- 交易行显示置信度和账单日期；展开后显示采集时间。
- 去重键优先订单号；无订单号时使用来源、类型、金额、方向、商户和事件时间/时间桶；10 分钟内存窗口防止同一卡重复写入。
- 数据库版本 v8，7→8 非破坏迁移。

### 官方账单导入

- 实际微信账单解析：368 条有效，0 错误，49 条退款；60 条转账/提现 + 5 条红包收入。
- 映射：322 条支出，46 条收入。
- 重复导入校验：同一文件第二次导入 `reimportValid=0`。
- 跨来源去重：无单号通知/页面记录按来源、金额、方向、商户和 2 分钟窗口匹配；导入行有单号而旧记录无单号时，30 秒同事件窗口兜底。
- 预览阶段与确认阶段使用同一套精确 + 模糊去重，避免“预览 1 笔、确认 0 笔”的计数不一致。
- 退款行保留为 `refund` 状态，原始支出也保留但统计排除。
- 提现（方向 `/`）保留为转账类支出，统计排除。
- 修复 XLSX Excel serial 时间偏移：旧算法用 `Asia/Shanghai` 1899 年历史偏移 `+08:05:43` 作为锚点，导致所有时间早 343 秒；现改为先还原日历字段，再按目标时区现代偏移换算。实机导入第 19 行时间已恢复为 `2026-11-14 15:31:58 +08:00`（epoch `1794641518000`），并加 serial 单测。
- XLSX 预览行号按工作表真实行号显示，跳过空行也不会偏移。

### 分类

- 导入分类先用商户列匹配 `CategoryClassifier`，只有商户为空或为“微信支付/支付宝”等泛化名称时才用原始上下文；避免“交通银行/充值”等字段覆盖已识别商户。
- 复验发现的错分已修：中国电信→水电、自来充→水电、拼多多→购物、腾讯公益→其他、炸鸡店→餐饮、发给个人→转账并排除统计。
- 复验还发现“商户优先”会把个人转账/红包（商户只是人名）降级为 OTHER，导致统计虚高；现已同时检查原始账单字段中的转账/转入/转出/汇款/提现/发给/微信红包/信用卡还款提示。收到的红包单独识别为收入（`unverified`），其余转账仍保留 transfer 排除，避免把家人/自己账户间移动算成收入。
- 转账提示只在商户本身无法分类时生效；已知商户不会被原始字段里的“红包”误判为转账。
- 通用分类器改为“商户字段优先 → 上下文兜底”；同一字段内按最长关键词命中，分类顺序只在关键词等长时兜底。这样 `Apple Music` 归娱乐而不是购物、`美团单车` 归交通而不是餐饮、`美团买药` 归医疗、`抖音商城` 归购物。参考了 AutoBook 的“用户商户规则优先 + 内置关键词表”和 Firefly III 的规则引擎思路，但没有引入外部依赖。
- 增加红包优惠负向规则：`红包抵扣/红包优惠/红包封面` 不再命中转账分类；`基金会/公益基金` 不命中理财。
- 页面识别不再固定写 OTHER，改为按页面商户 + 页面文本调用分类器；转账、退款、提现仍按卡片类型覆盖。
- 手动修改交易分类或确认扫描结果时，会按归一化商户记住分类，写入 DataStore；设置页“自动分类 → 商户分类记忆”可新增、删除、查看和清除规则。
- 运行状态稳定性：保留已连接起始时间，进程重启/短时 rebind 不把运行时长归零；断连后 3 秒尝试 `requestRebind`；每 15 分钟 WorkManager 检查并尝试恢复常驻服务。长断连、重启或心跳过期仍会重新计时，避免显示虚假的长时间运行。
- 运行时长归零根因：旧实现每次 `onListenerConnected` 都覆盖 `connectedAt`，且 `KeepAliveService.startedAtMs` 是进程静态值；ROM 杀进程/服务或解绑监听后重连就会从 0 开始。现在用 wall clock + 最近心跳/断连时间判断是否保留起始时间，重启/长断连才重置。
- 设置页规则编辑器冒烟：最终 APK 启动正常，新增 `testshopen → 餐饮` 成功出现，删除后恢复空态；未清理用户原有应用数据。
- 补充常见品牌词典：餐饮、便利店/电商、出行、药房/健康、教育、保险/理财、水电等；具体品牌表在 `CategoryClassifier`。
- 新增 BONUS（奖金）、INVESTMENT（理财）、INSURANCE（保险）、GIFT（红包）分类，并补了图标、颜色、筛选和预算入口；收到的红包归 GIFT 并计入收入。后端 `CATEGORIES` 白名单同步新增这四个分类。
- 最终实机导入分类核对：其他 83、购物 77、转账 60、餐饮 62、水电 57、娱乐 17、教育 4、交通 2、医疗 1、红包 5。

## 3. 当前完整流程

```text
支付发生
  ├─ 系统通知 ── 标题/正文解析（支付/转账/提现/红包/退款）── 去重 ── 入账
  │                                  └─ 转账/提现/发出红包标记 transfer；收到红包计收入
  ├─ 页面可见
  │    ├─ 无障碍节点卡片 ── 完成态判断 ── 扫描记录直接入账（带置信度/日期）
  │    └─ 节点不完整 ── 窗口截图 ── PaddleOCR/ML Kit ── 同一卡片解析 ── 入账/待核对
  └─ 无通知/secure 历史页
       └─ 官方 CSV/XLSX 导出 ── App 导入预览（精确+跨来源模糊去重）── 用户确认 ── 原子写入

银行短信 ── SMS 解析 ── 入账
手动记账 ── 直接入账
```

所有入口最终都进入同一账本和统计口径；退款、转账、提现、重复、不计入状态由现有规则排除。

## 5. rc.10 收尾（2026-11-16）

### 5.1 误记 `-¥2.00` 的根因

- 触发页面：微信聊天列表（`com.tencent.mm.ui.LauncherUI`）及聊天/搜索/小程序页。
- 聊天列表里“微信支付”服务号一行的预览是 `已支付¥2.00`；旧规则把 `已支付` 当作完成态支付标记，`amountAfterLabel` 从这行取出 2.00。
- 卡片分组把整页聊天行合并成一组，聊天标题（“615 宿舍”“神经研究所邑大分所”等）被当成商户候选；页面哈希变化后去重失效，于是每次切换页面都可能再记一笔。
- 这是“页面形态判断缺失”的问题，不是金额解析或商户分类单点错误；只删关键词会在下一个预览格式上复现。

### 5.2 修复

- 新增 `PageActivityGuard`：在进入卡片解析前按页面形态拦截微信聊天列表、聊天页、通讯录、搜索、服务号、文章页，以及支付宝首页/消息/聊天页。
- 小程序/H5 容器（`WxaLite*UI`、`WebViewUI`、`AppBrandUI`）不再一律拦截：只有页面同时出现强成功状态（支付成功/付款成功/交易成功等）和金额时才放行，真实商户支付结果页仍可采集。
- 群收款/活动收款页在缺少本人强成功支付时整页拦截；`你无需支付/他人已支付/对方已支付/代付` 作为负向标记拒绝。
- 支付卡片解析要求弱标记（`已支付/已付款/支出/消费`）必须同时有商户、订单号或支付方式等上下文；纯聊天预览不再成立。
- `lastWindowActivity` 只接受 Activity 类名，弹窗、输入法、Popup 不再污染当前页面判断；避免聊天页绕过 activity 检查或真实支付页被残留类名误挡。
- 同屏出现多张完成卡时不再批量入账，视为历史账单列表，交给显式账单导入；符合“后台不静默抓取历史列表”的既有约定。

### 5.3 收入口径与 UI

- Android 统计（日/月/年）和交易列表日汇总现在计入所有 `INCOME`，包括转账/红包收入；支出仍排除转账、退款、提现和重复记录。
- 后端 `summary`、Wallos ledger、integration 的 `valid` 口径同步为“收入全计，支出排除 TRANSFER/transfer 状态”，前后端一致。
- 交易列表筛选改为单选，`全部` 可清空其他维度；收入筛选保留但日汇总不再把转账收入算成“未计入”。
- 交易行展开后提供分类规则、编辑、删除、计入/不计入；新增商户规则编辑器。
- 设置页同步项、语言按钮、更新卡片对齐；更新检查只取稳定版，支持应用内下载签名 APK。
- 设置页“导入账单”直接打开导入对话框；统计页增加月度/全年切换与年份步进。
