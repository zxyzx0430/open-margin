# 清衡 Android 16 无障碍验收（健康检测、故障记录、真机）

目标：验证 **2 实际连接健康检测、3 本地诊断、4 Android 16 兼容性**。
**不在本变更中**修复事件节流、遍历节点上限或 ANR 风险（原优先级第 1 项）。
不触碰生产账本，不删除/重装正式 APK，不更改签名证书。

## 软件测试（已添加自动化，结果以 GitHub Actions 为准）

- `AccessibilityConnectionStateTest` 检查已授权但未连接时不得显示“运行中”。
- `android-emulator-smoke.yml` 在 Android API 35/36 分别启动应用，用模拟器专用 ADB 设置授权，然后从 debug 日志确认 `onServiceConnected` 被调用。
- CI 构建通过、模拟器绑定通过不等于 HyperOS / Android 16 **真机**通过。
- 模拟器不应包含真实支付和聊天数据。

## 真机步骤（必须在 Android 16 手机上执行才能勾选）

1. 在清衡记录版本号；不卸载、不清除数据。确保旧交易已同步/备份。
2. 手机连接电脑，启用 USB 调试，运行 `adb devices`，确认 `device` 状态。
3. 设置 → 无障碍 → 清衡：人工重新开启（已开启可先关闭再开启）。如果出现“此服务出现故障”，**立即记录时间**，不要清除数据。
4. 清衡 → 设置 → 无障碍兜底：点击“刷新实际运行状态”。验证 UI 显示“服务已连接”。仅“已授权”不算通过；“上次页面事件”未变更也不一定是错误。
5. 打开微信、支付宝各一次，只浏览非敏感页面，返回清衡刷新，确认“上次页面事件”在操作后更新。
6. 切至后台、锁屏、等待 15–30 分钟；解锁并重复第 4–5 步。验证是否断连或出现新增异常。
7. 重启手机后重复第 4–5 步，确认服务可在系统允许的条件下重新连接。
8. Windows PowerShell 在仓库根目录运行 `powershell -ExecutionPolicy Bypass -File .\scripts\Check-Android16Accessibility.ps1`。若安装了 debug 构建，将参数改为 `-PackageName com.bookkeeping.app.sync2`。
9. 验收结果：Android 版本、ROM、清衡版本、连接/页面事件时间、是否故障、最近异常阶段和类名、是否重启恢复。**不记录聊天正文、金额、订单号、完整 logcat 或银行卡信息**。

### 验收标准

- **PASS:** Android 16 真机上实际连接；打开微信/支付宝时页面事件更新时间前进；后台、锁屏与重启后可正常恢复；测试期间不再出现系统“此服务出现故障”；无新增应用异常。
- **FAIL:** 出现系统故障提示，或“已授权但未连接”持续存在，或开启相关应用后仍无任何页面事件。将 UI 的最近异常类型与时间作为最小诊断信息。
- **BLOCKED:** 无法访问 Android 16 真机/ADB，则明确报告“真机未验证”，不能以 CI 替代。

### 局限

Android 16 系统模拟器不模拟特定厂商的后台清理策略。该健康检查验证服务生命周期，**不保证**微信支付服务消息能被识别，也不等于支付账单完整性审计。
