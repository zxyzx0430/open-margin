# 新建账单对话框：紧凑单屏布局

## 布局

- 主表单不使用纵向滚动。`AlertDialog` 外层加 `imePadding()`；键盘弹出时由 IME inset 调整对话框位置，表单不切回纵向滚动页。
- 一句话记账放在首位：标签并入输入框，输入区固定至少 2 行、最多 3 行；示例缩短为「例：午餐 36 元，微信支付」，说明缩短为「可留空；识别后自动填表」。
- 支出/收入仍是同一行的两个 chip。
- 日期与金额同一行：日期按钮宽 100dp，预览显示 `MM/dd`；金额输入框占剩余宽度。
- 分类和商户同一行：分类下拉与商户输入框按 1:1.15 分配剩余宽度。
- 账户标签与 5 个常用 chip 同排。chip 使用 `labelSmall`、4dp 间隔；窄屏时只允许这一行横向滚动，不折行。编辑已有自定义账户时仍额外显示对应 chip。
- 备注保留为单行输入框；字段、回调和解析/保存路径不变。

## 尺寸预算与取舍

内容区垂直预算（dp，按 Material 3 常规控件高度估算；不是模拟器实测）：一句话输入及说明约 107、类型 chip 40、日期/金额行 56、分类/商户行 56、账户行 40、备注 56，五处行间距共 30，表单主体约 **385dp**。标题、按钮和 AlertDialog 自身留白另计。

360×640dp 与 412×915dp 使用同一套纵向行数，不增加滚动。360dp 下优先压缩日期预览、提示文字和账户 chip 字号；金额占同行主要宽度，账户项保持单行并可横向触达。412dp 下账户项通常有更多横向空间。若字体缩放或错误提示增加高度，优先保留标题、字段和取消/保存按钮，不通过添加纵向滚动补救。

## 键盘与验证边界

键盘模式使用 `imePadding()`，没有纵向滚动容器；一句话输入框的 Done 动作仍执行原有解析提交行为。IME 会缩小实际可视区域，打开键盘时对话框是否能在目标机型上同时露出所有字段及底部按钮，需在 360×640dp 真机/模拟器复核；此提交环境没有 Android SDK，未做真机截图验证。验收时重点检查金额、商户、备注聚焦后的按钮可见性、账户 chip 横向触达，以及 1.0×/大字体设置下的裁切。
