# 2026-10-12 Wallos 日常消费图表和导航一致性修复

## 问题与根因

- 选中 ¥12.30 的低支出日，实心柱实际高度很低，却出现近乎整张图高度的蓝色空心高亮框；¥91.36 的高支出日看起来正常。
- 源码中焦点层 `.finance-daily-focus-band` 被固定设置为 `apexcharts-grid` 的完整高度，而非对应支出的柱高。原有选中 SVG 还被 `scaleY(1.08)` 再次拉伸。因此金额正确但高亮误导。
- 手机导航的「日常消费」使用 FontAwesome 实心钱包，与其余 Wallos 原生的 50×50 SVG 线描图标和 20×20 CSS 尺寸不一致。

## 修改

1. 选中高亮直接测量 ApexCharts SVG 柱 `getBoundingClientRect()`，以实际柱子的 top、width、height 绘制描边，不再占据全幅图高。
2. 去掉 SVG 选中最终态的垂直放大。实心柱与高亮轮廓共享最终的真实高度；同时使用约 540ms 的 `scaleY` 从较高视觉起点收缩到实际高度，重复选中重新播放。低于绘图像素的金额或零金额显示底线上的小标记。
3. 若 ApexCharts 由于布局/主题切换替换 SVG 柱子，观察器会在下一帧恢复所选日期描边，避免标签和图表暂时脱节。
4. 对减少动态效果的系统偏好取消动画，仍保留选中态；原有日期选择、点击整列、自动水平滚动、金额明细和排除金额功能不变。
5. 新增 `mobile-menu-expenses.php`，采用 Wallos 一致的 50×50 viewBox、`currentColor` 线条、20×20 实际尺寸，替换 FontAwesome 实心钱包；通过 Dockerfile 安装并加入发布哈希校验。
6. 更新 Service Worker 缓存版本，避免移动端缓存旧图表脚本。

## 验收

- 合成 ¥91.36 与 ¥12.30 相邻高矮柱：在 320/390/768/1440px、明暗主题测试轮廓与实柱高度差和顶部差均小于 4px，低柱轮廓高度小于绘图区一半；重复选择动画类重新启动。
- 在 320/390/768px 的真实 Wallos 菜单测试图标：新「日常消费」与「日历」均为 20×20px 且 50×50 viewBox，移动端布局无新增裁切。
- 对无消费、异常大值、二月、闰年、年末及退款/转账排除数据执行原有浏览器回归；前端完整 PHP 渲染与 PHP/JS 语法检查通过。
- 不改变 SQLite 财务交易数据和汇率计算；只更新 UI 脚本、样式、图标、发布配置。
