# Wallos Finance 消费趋势图表验收与修复（2026-10-12）

## 用户复现现象

在手机的 Wallos「统计 → 消费趋势」，点击 11 日 ¥91.36 柱子却可能出现「01 日 ¥0」的 ApexCharts 原生 tooltip，点击后选中蓝色光柱、轮廓与日期卡片丢失。「7天」误显示月末 25–31 日的未来日期。

## 确认根因

1. 统计页复用 ApexCharts，但未复用「日常消费」另一套已修好的选择逻辑；原生 tooltip 对手机点击映射错误。
2. 图表容器意外设置 `data-finance-range`，父组件会把任何柱子点击判作“切换 7 天／整月”，销毁并重新生成图表，刚绘制的高亮及日期卡片因此丢失。这是关键逻辑冲突。
3. ApexCharts 可能在原生 SVG click 处理阶段替换内部节点，导致沿旧图形节点向上查找容器返回 null；调用日期选择时出现 JS 异常。
4. 过去的「7天」选了月份后 7 个数组元素，当前月份的月末未来日期与真实“最近 7 天”不符。

## 修复

- 使用独立 `data-finance-chart-range` 保存图表当前模式；只有原生切换按钮继续使用 `data-finance-range`，点击图表不会意外切换范围或重绘。
- 禁用统计图表 ApexCharts 默认悬浮提示；使用 SVG path 真实 `j` 日期索引，空白列才做几何定位；在原生点击结束后稳定选择日期，避免访问已脱离 DOM 的节点。
- 高亮层独立于 ApexCharts 的 SVG 子树，按真实柱子的 bounding box 设置描边，不随图表重绘丢失；动画约 520ms 从较高位置收缩到真实金额高度；用户启用减少动态效果时不播放。
- 选中日期在图表下显示专用控件，日期、金额与查看当天流水联动，并确保切换 7 天和整月不出现重复控件。
- 最近 7 天以北京时间实际今天结束；2026-10-12 的范围是 2026-10-06 至 2026-10-12，不显示未来日期。
- 修改 PHP 图表容器的语义角色和 Service Worker 缓存版本，避免手机加载旧 JS。

## 数据与生产边界

不改 Finance 或 Wallos 的交易金额、审核状态、数据库结构、订阅费用、动态汇率。其它原生订阅预测统计维持生产最新修复的完整年份标签。

## 验收门禁

1. 320 / 390 / 768 / 1440 CSS 像素 x 亮暗主题，8 组真实 Wallos PHP 页面 + Chromium 测试。
2. 点击 11 日、12 日：日期分别等于 2026-10-11／2026-10-12，卡片显示 ¥91.36／¥12.30；蓝色实柱与轮廓最终高度和顶部相差小于 4px，重复点击会触发动画，无原生错误日期 tooltip。
3. 切换「7天」：2026-10-06 至 12，只有 7 根柱，选择框同范围；当日流水点击能正常打开且无未授权写操作。
4. 对仪表盘、日历、统计页原有脚本回归，以及 JS/PHP 语法、公开仓库检查、静态资源哈希校验。
5. 生产部署前保持 SQLite 在线备份及自动回滚镜像；生产数据不用于浏览器写入测试。
