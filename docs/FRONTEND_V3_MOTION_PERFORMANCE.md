# P6 motion performance

Design retained: calendar live height tracking, 40% / 85% snap points and dismissal rules; wallet six-card stack and vertical rubber-band drag, now initiated on front header; bottom chrome capsule dimensions; receipt and press feedback, segmented control, switch, large title and VoiceFab gesture state machine. No capture, transaction semantics, SDK, runtime dependency or release signing changes.

Implementation fixes: use idle-only native backdrop capture on overlapping tabs, tinted fallback during scrolling/navigation, explicit material capability/fallback text, distinguish stronger translucency and highlight. Calendar drawer height reads move to measurement phase without changing physical behavior; memoize day total. Sheet opens from 96dp and closes to measured panel height; preserve save guard, keyboard, scrim and drag spring. Day groups now use stable-key lazy headers and rows, joined visually into one card; target row index accounts for all conditional preceding sections. Tap haptic only on completed non-scroll gesture; highlight animation reads in draw phase; category expansion no repeated layout animation; pie state keyed by category and respects reduced motion; merchant bitmap cache bounded to 4 MiB.

Validation: focused JVM tests for lazy row index and existing motion/material/deck tests; GitHub Actions is the acceptance gate. No measured device FPS claimed; real-device inspection still required for scroll smoothness, sheet drag and 3/6-card behavior. Full-page native recording still exists when stationary on supported devices; no claim of cropped recording or native refraction. Calendar intentionally does not record a backdrop because the drawer and content do not overlap the bar.
