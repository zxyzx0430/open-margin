# 录音音频焦点与电脑配对入口

## 录音处理策略

采集格式和识别接口保持不变：16 kHz、单声道、PCM16，每批 1,600 个样本（100 ms）。音频仍在设备本地处理。

每次开始采集时按以下顺序选择输入源：

1. 创建 `VOICE_RECOGNITION` 的 `AudioRecord`，读取 `audioSessionId`，尝试创建并启用 `AcousticEchoCanceler` 与 `NoiseSuppressor`。两种效果分别处理：AEC 成功就保留该输入源；NoiseSuppressor 不可用不会阻止录音。
2. 如果 AEC 不可用、创建失败或启用失败，释放首个 `AudioRecord` 及效果对象，再创建 `VOICE_COMMUNICATION` 输入源（系统通信音源，带通信回声处理）。同时仍尝试附加 AEC/NS。
3. 如果 `VOICE_COMMUNICATION` 无法初始化或启动，再创建 `VOICE_RECOGNITION` 作为最终回退；效果可用时仍启用，不可用时记录警告并继续录音。

AEC/NS 不可用、创建失败或启用失败都会写 `Log.w`，不会因效果缺失直接崩溃。停止或释放时释放效果对象；采集启动失败时也会释放已申请的音频焦点和临时资源。

## 音频焦点

录音启动时、创建 `AudioRecord` 之前申请短时独占焦点：

- API 26+：`AudioFocusRequest`，`AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE`；`AudioAttributes` 为 `USAGE_VOICE_COMMUNICATION` + `CONTENT_TYPE_SPEECH`，不接受延迟获取。
- API 24–25：旧 `requestAudioFocus` 接口，`STREAM_MUSIC` + `AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE`。
- 结束、取消、初始化/采集失败和引擎关闭都会 abandon；释放操作幂等，不永久占用焦点。若系统拒绝焦点，应用记录警告但仍允许采集。

预期行为是音乐应用遵守焦点变化时暂停或降低音量，录音结束后恢复。不同音乐应用和厂商 ROM 对焦点的响应可能不同，必须在真机确认。

## 设置里的电脑配对入口

入口位于「设置 → 同步」区域，与「同步设置」和同步状态相邻，标题为「配对电脑」。说明页只列出配对后新增的能力：

- 手机、电脑、网页多端同步；
- 电脑端看板：长期趋势、订阅预测、对账、重复复核；
- MCP 接入自己的 AI 客户端：查账、记账、改账、管理订阅、设置预算。

说明页标题栏右上角固定显示带二维码图标的「扫一扫」按钮，直接打开相机，不经过三步向导。扫码成功后进入现有连接验证步骤，使用 QR 中的账本身份执行只读验证；仍需用户显式确认后才启用同步。无法扫码时可点「手动填写地址和密钥」，继续使用原向导中的手动配置流程。向导的验证和启用规则保持不变。

## 自动化测试与真机清单

纯 JVM 单测覆盖焦点请求配置（短时独占、通信用途、语音内容、旧接口音乐流）及 AEC 缺失时的输入源回退顺序。英文界面测试覆盖设置入口、说明页文案和扫一扫按钮；`TranslationCoverageTest` 扫描新增的 `tr()` 文案。

以下项目需要真机验证，CI 编译/单测不能代替：

- [ ] **扬声器播放音乐时长按说话**：确认录音期间音乐暂停或被 duck，停止后恢复；检查不同音乐应用的表现。
- [ ] 用 Logcat 确认设备实际选择的输入源，以及 AEC/NS 启用状态；AEC 不可用设备仍能录音。
- [ ] 正常停止、取消、关闭面板、拒绝麦克风权限、麦克风被占用及录音初始化失败后，音乐焦点均已释放。
- [ ] API 24/25 的旧焦点接口，以及 API 26+ 的 `AudioFocusRequest` 路径。
- [ ] 从设置直接点「配对电脑」→ 右上角「扫一扫」开相机；首次授权、取消扫描、无效二维码和成功扫描都能正确返回。
- [ ] 成功扫码后 URL、设备密钥和账本身份进入验证步骤；未通过只读验证或未确认时不启用同步。
- [ ] 「手动填写地址和密钥」仍能进入原有手动配置流程；英文界面标题、说明和按钮不截断。
