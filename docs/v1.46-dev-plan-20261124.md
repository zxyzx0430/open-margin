## 2. 模块一：续费管理与端云双向同步

### 2.1 Android 本地数据层（Room DB `v13 -> v14`）

在 `BookkeepingDatabase.kt` 中升级版本号至 `14`，新增 `MIGRATION_13_14`（纯增量建表，不改现有表结构）。

#### 新增表：`subscriptions`

| 字段名 | SQLite 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | 本地自增主键 |
| `syncUuid` | `TEXT NOT NULL UNIQUE` | 全局唯一 UUID，端云双向同步幂等主键 |
| `wallosId` | `INTEGER` | 服务端 Wallos 订阅 ID（单机用户为 `NULL`） |
| `name` | `TEXT NOT NULL` | 订阅名称（如 `OpenAI · ChatGPT Plus`、`淘宝 88VIP`） |
| `amountCents` | `INTEGER NOT NULL` | 原币种金额（分） |
| `currency` | `TEXT NOT NULL DEFAULT 'CNY'` | 币种代码（`CNY`/`USD`/`HKD`/`EUR`/`JPY`/`GBP`） |
| `cnyEstimateCents` | `INTEGER` | 折合人民币估算（分，便于外币展示 `¥133.16 (US$19.99)`） |
| `cadence` | `TEXT NOT NULL` | 周期：`weekly` / `monthly` / `quarterly` / `yearly`（与 `wallos_api.py` 的 `CYCLES` 严格对齐） |
| `nextDueMs` | `INTEGER NOT NULL` | 下次扣款时间戳（毫秒，本地时区当天 00:00） |
| `startMs` | `INTEGER` | 订阅开始时间戳（可选） |
| `paymentChannel` | `TEXT NOT NULL DEFAULT ''` | 支付渠道（如 `微信`、`支付宝`、`银行卡`、`未指定（待确认）`） |
| `autoRenew` | `INTEGER NOT NULL DEFAULT 1` | `1`=自动续费，`0`=需手动续费 |
| `pendingCancel` | `INTEGER NOT NULL DEFAULT 0` | `1`=标记「准备取消/待退订」（对应网页版 `upcoming_cancellations`） |
| `notifyEnabled` | `INTEGER NOT NULL DEFAULT 1` | 是否开启本地到期提醒 |
| `notifyDaysBefore` | `INTEGER NOT NULL DEFAULT 3` | 提前几天提醒（默认 3 天） |
| `active` | `INTEGER NOT NULL DEFAULT 1` | `1`=生效中，`0`=已停用（保留历史） |
| `note` | `TEXT NOT NULL DEFAULT ''` | 备注 |
| `updatedAtMs` | `INTEGER NOT NULL` | 最后修改时间戳（LWW 冲突裁决基准） |
| `deletedAtMs` | `INTEGER` | 软删除墓碑时间戳 |
| `dirty` | `INTEGER NOT NULL DEFAULT 1` | `1`=待推送服务端，`0`=已同步 |

### 2.2 日历页与「全部订阅」UI/UX 细则

1. **日历页「本月续费」胶囊摘要条（`CalendarScreen.kt`）**：
   - 紧贴在「支出 / 收入 / 结余」行下方、月历网格上方；
   - 有活跃订阅时展示：`↻ 本月续费 4 笔 · ¥261.86（待扣 ¥10）` + 右侧 `全部 ›`；
   - **智能空态（防冰冷 0 元）**：订阅数为 0 时，绝不展示 `0 笔 · ¥0`；若本地账单已探测到疑似连续扣费，显示惊喜引导 `✨ 发现 N 项疑似自动续费，一键管理 ›`，否则收起为极轻的单行引导 `管理周期续费 · 添加 ›`。
   - **月历圆点防打架配色**：为避开现有日历粉红（支出）与浅绿/深森绿（收入/选中）热力底色，常规续费点采用 **清透靛蓝 `#3B82F6`**，准备取消采用 **琥珀金橙 `#F59E0B`**，并统一带 **1.5dp 白色外描边（Halo Ring）**，保证任何底色下都清晰精致。
   - **日历底部抽屉分层（防误解重复记账）**：选中日期下方先展示独立细边框分组的「当日续费计划」（带 `待扣` / `✓ 本期已入账` 徽章），下方以极细分隔线 + `当日流水 · N 笔` 过渡到真实交易流水；当本期已被账单匹配时自动弱化为 `✓ 本期已入账` 且不计入「本月待扣」。
2. **「全部订阅」二级页（`SubscriptionsManageScreen.kt`）**：
   - 顶部支持状态筛选胶囊：`全部 / 即将到期 / 准备取消 / 已停用` + 右上角 `+ 新建`；
   - 底部附一行极轻说明：「订阅仅用于排期提醒，实际支出以账单流水为准，不会重复计入总支出」；
   - **智能发现横幅**：使用 Kotlin 移植版 `RecurringCandidateDetector.kt`（对齐 `backend/features.py` 的 `recurring_candidates` 算法），从本地近 6~12 个月流水中识别同商户、同金额的周期性支出，一键点击「转为订阅」自动预填表单；
   - **等高两行紧凑卡片（无左滑冲突、无 `⋮` 菜单）**：
     - 左：柔和浅绿/品牌圆角徽标；
     - 中：第 1 行 `名称 + 状态胶囊（琥珀橙「待取消」/ 灰「手动」）`；第 2 行 `3天后扣款 · 每月 · 花呗`；
     - 右（强制等高两行 + 等宽数字 `tnum`）：第 1 行永远为折合人民币主金额 `¥133.16`；第 2 行外币显示 `原价 $19.99`，人民币显示 `12月15日`（到期日），确保整表视觉整齐。
3. **沉浸式订阅详情抽屉（`SubscriptionDetailSheet`）**：
   - 点击任意订阅卡片弹出半屏 `ModalBottomSheet`（与「新建账单」抽屉视觉统一）：
     - **顶部**：服务名 + 金额 + 倒计时标签 + 账单联动摘要（如 `近一年已匹配 11 笔 · 累计 ¥1,464`）；
     - **中部（免跳转直接开关）**：`自动续费`、`准备取消`、`到期提醒（提前 N 天）`；
     - **底部动作栏**：主按钮（森绿）`已扣款 · 推至下期`；次按钮 `编辑`、`停用（保留历史）`；
     - **彻底删除**：收在「编辑订阅」页最底部并带二次确认，防止误删。

### 2.3 自动周期推进与本地到期提醒

- **自动推进下次扣款日**：
  - 当到期日已过（且 `autoRenew = 1`），或自动采集/导入记入一笔命中活跃订阅的新支出（商户匹配 + 金额误差 ≤ 5% + 到期日前后 3 天内）时，系统自动将 `nextDueMs` 推进至下一周期（与 Wallos 一致），并在详情抽屉标明最新一期状态。
- **克制的本地通知（`SubscriptionReminderWorker.kt`）**：
  - 每日定时扫描一次，统一在到期前 `notifyDaysBefore` 天（默认 3 天）弹 **1 条** 本地通知：
    - 常规订阅：`[续费提醒] 手机话费 将在 3 天后扣费 ¥47（微信）`；
    - 标记「准备取消」：`[准备取消] 腾讯视频 将在 3 天后自动续费 ¥25，记得去关闭自动续费`。

### 2.4 端云双向同步协议（Android ↔ Backend ↔ Wallos）

#### 1. 后端轻量映射表（位于 Finance SQLite，绝不直写 Wallos SQLite）
在 `backend/sync_v2.py` 中新增：
```sql
CREATE TABLE IF NOT EXISTS subscription_sync_meta (
    sync_uuid TEXT PRIMARY KEY,
    wallos_id INTEGER UNIQUE,
    pending_cancel INTEGER NOT NULL DEFAULT 0,
    note TEXT NOT NULL DEFAULT '',
    updated_at_ms INTEGER NOT NULL,
    deleted_at_ms INTEGER,
    last_wallos_hash TEXT NOT NULL DEFAULT ''
);
```

#### 2. 新增同步接口（复用 `X-Device-Token` 设备鉴权）
- **`GET /api/v2/sync/subscriptions`**：
  - 调用 `wallos_api.get_all()` 拉取 Wallos 最新订阅，与 `subscription_sync_meta` 对账（网页新建自动分配 `sync_uuid`，网页修改更新 `updated_at_ms`，网页删除打上 `deleted_at_ms` 墓碑）；
  - 返回全量订阅快照 + 墓碑列表 + 当前参考汇率 `fx_rates` + `server_id`。
- **`POST /api/v2/sync/subscriptions/push`**：
  - 接收 Android 端 `dirty = 1` 变更数组；
  - 新建走 `wallos_api.add(...)`；更新按 `updated_at_ms` 采用 Last-Write-Wins 并走 `wallos_api.edit(...)`；彻底删除走 `wallos_api.delete(...)` 并写墓碑；
  - 返回 `sync_uuid -> wallos_id` 映射及服务端最新快照。

#### 3. Wallos 国人常用支付渠道扩展（`backend/wallos_api.py` & 部署补齐）
- 在 `wallos_api.py` 的 `valid_subscription_links` 中扩展国人常用支付方式支持：**`微信` / `支付宝` / `花呗` / `银行卡（信用卡/储蓄卡）` / `云闪付` / `京东白条` / `Apple Pay` / `抖音支付` / `未指定（待确认）`**；
- **Wallos 端配置与安全回落**：
  - 在部署/初始化脚本中自动为 Wallos `payment_methods` 补齐常用中文渠道（如 `花呗`、`云闪付`、`京东白条`、`Apple Pay`）；
  - 若某实例尚未启用对应渠道或用户输入了自定义渠道名（如「招行储蓄卡」），`wallos_api.py` 不再硬报错中断同步，而是安全回落映射到 Wallos 已有最接近渠道（如 `AliPay` / `Credit Card` / `未指定`），同时在 `subscription_sync_meta` 中完整保留原始渠道名，保证手机端永远显示精确名称且同步零失败。

#### 4. Android 端接入（`BidirectionalSyncClient.kt`）与外币汇率兜底
- 在现有 `sync()` 流程完成 `verifyServerIdentity()` 和交易同步后，串联 `syncSubscriptions()`（先 `push` 本地脏数据，再 `pull` 远端快照合并）；
- 本地永远先保存成功（离线秒生效），若同步受阻则在订阅页顶部展示柔和提示条 `N 项待同步，联网后自动同步`，不阻塞编辑；
- **外币折算兜底**：联网同步时使用服务端返回的 `fx_rates` 计算 `cnyEstimateCents`；纯单机/离线用户内置一份轻量默认参考汇率表（USD/HKD/EUR/JPY/GBP → CNY），同样能正常展示折合人民币估算。

## 3. 模块二：统计页重设计与功能增强（`StatsScreen.kt` & `StatsViewModel.kt`）

### 3.1 顶层视觉重设计
- **顶栏**：左侧标题 `统计`，移除右上角孤立的日期按钮，留白更清爽；
- **第一层（核心视角切换）**：精致分段切换 **`支出 | 收入 | 订阅`**；
- **第二层（合并轻量筛选行，仅 `支出 / 收入` 下展示）**：
  - 左侧紧凑小胶囊：`日` · `月` · `年`；
  - 右侧日期选择器：`2026年11月 ▾`；**小屏适配（360dp 防撞车）**：「日」视图当年省略年份，精简显示为 `< 11月24日 >`（跨年显示 `25/11/24`），确保单行留白充裕不换行；
  - 切到 `订阅` 时隐藏该行，首屏直接进入订阅分析。

### 3.2 `支出 / 收入` 视图新增「按账户支出分布」
- 位于「分类占比（圆环）」下方、「趋势柱状图」上方；
- 采用**轻量横向进度条卡片**（不画第二个大圆环，保持页面节奏疏密有致），按 `transaction.account` 复用 `StatsTransactionPolicy` 口径聚合展示；
- **同义归并 + 长尾折叠 + 空态保护**：
  - 常见同义名展示归一化（如 `微信支付` / `微信零钱` 归并到 `微信`），空值统一归为「未归类账户」排在最后；
  - 默认只展开 **Top 5 账户**，第 6 名及以后收纳为 `展开其余 N 个账户 ▾`，防止页面拉得过长；
  - 若当期 >90% 账单未填账户，自动折叠为轻量提示行，不展示「未归类账户 100%」的废卡片；
- `StatsLedgerDrilldown` 新增可选字段 `val account: String? = null`，点击任意账户条直接下钻到账单页查看该账户在当前时间范围的明细。

### 3.3 `订阅` 视图（借鉴网页版 `stats.php`）
- **无订阅引导态**：若尚无订阅，展示一句清晰说明 + 两个主按钮：`从历史账单自动发现` 与 `手动添加第一条订阅`；
- **月均固定成本总览卡**（森绿柔和主题，与支出总览卡同源设计）；
- **订阅结构 4 格指标卡**：在用周期订阅数 / 平均每项月费 / 最高月费订阅 / 需手动续费数；
- **「准备取消 · 潜在省钱」高亮条**：当存在 `pendingCancel = 1` 的订阅时展示 `退订后每月可省 ¥XX`，点击跳转「全部订阅（待取消筛选）」；
- **未来 12 个月续费预测柱状图**：按月投影未来 12 个月预计扣款总额，高亮标注**年费峰值月**（如 `峰值：2027年3月 ¥1,087`），右上角提供 `全部订阅 ›` 直达管理页。

## 5. 模块四：统一「数据迁移与备份」（单文件 `.zip` 完整备份/恢复）

升级设置页现有导入/导出入口为统一的 **「数据迁移与备份」** 面板：
- **导入区**：一键选择文件，自动识别微信 / 支付宝 / 清衡 / 钱迹 / 一木 / 鲨鱼账单；
- **备份与换机区**：
  - `导出账单 CSV`（面向表格分析）；
  - `导出完整备份 (.zip)`：默认不含原图（体积极小，几百 KB 秒传），提供可选开关「同时打包票据原图」；
  - `从完整备份 (.zip) 恢复`：先解析 `manifest.json` 预览各项数量（如 `预计新增 X 笔账单 · 自动跳过 Y 笔已存在`），用大白话明确承诺「**安全合并模式：只补齐缺失记录，绝不删除本机现有任何数据**」，支持勾选模块合并恢复。

#### 备份包目录规范（严禁导出设备 Token / 密码等敏感凭证）
```text
open-margin-backup-YYYYMMDD-HHmm.zip
├── manifest.json          # schemaVersion=1、App版本、导出时间、各模块条数与校验和
├── transactions.csv       # 清衡标准 CSV
├── subscriptions.json     # 全量订阅（含 syncUuid、周期、待取消、提醒配置）
├── budgets.json           # BudgetSettings（总预算 + 分类预算）
├── merchant_rules.json    # 商户自动分类规则
├── settings.json          # 非敏感偏好配置
└── evidence/              # （仅勾选「包含原图」时打包）本地截屏/票据原图
```
